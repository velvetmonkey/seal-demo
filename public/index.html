seal — a verified policy decision point for AI agents

seal sits between an autonomous agent and its tools. Every tool call passes through a decision procedure proven correct in Lean 4. The model can be jailbroken, confused, or confidently wrong. The boundary holds anyway, because it is a theorem, and theorems do not get jailbroken.

Everyone else is making the model safer. seal makes the model irrelevant to safety.

What is proven, and what is not

Proven
For a canonical action and trusted config, the combined verdict is allow iff every gating kernel allows, by the composition theorem. Axioms: {propext, Classical.choice, Quot.sound} only.
Trusted (TCB)
Lean compiler + runtime · host transport routes faithfully (fail-closed) · SealV2 canonical parser · the C ABI / FFI seam
Not claimed
model safety · classifier completeness · out-of-band effects · anything outside the MCP boundary

The kernel proves the decision, not the whole stack. Naming the trusted base on the page is the point, not a disclaimer: a small, honest, named TCB is the entire premise of safeguarded AI.
